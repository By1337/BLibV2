# Уведомления об изменениях состояния

Общая шина доступна через существующий фасад библиотеки `dev.by1337.core.BCore.events()`
после включения BLib. Подписывающийся плагин должен объявить зависимость от BLib,
чтобы шина была включена до его `onEnable()`.

```java
Subscription subscription = BCore.events().on(this, "economy:balance", playerId -> {
    // playerId != null — конкретный игрок; null — глобальное изменение.
    // Здесь выполняется поток, вызвавший emit().
});

BCore.events().emit("economy:balance", playerId);
BCore.events().emit("economy:reload", null);
subscription.close(); // Можно повторять и вызывать прямо из обработчика.
```

`Subscription` реализует `Closeable`, но `close()` не объявляет checked exceptions.
Перегрузка `on(String, Consumer<@Nullable UUID>)` создаёт подписку без владельца:
её нужно закрывать самостоятельно, например через `BasePlugin.addCloseHook(...)`.
Для плагинов предпочтительна `on(Plugin, String, Consumer<@Nullable UUID>)`:
все подписки владельца автоматически удаляются при `PluginDisableEvent`.
Попытка подписать отключённый плагин отклоняется по `Plugin.isEnabled()`.
При каждом включении плагин заново регистрирует подписки из своего `onEnable()`,
в том числе при повторном использовании того же экземпляра Plugin.
Ожидать `PluginEnableEvent` не требуется; старые подписки не восстанавливаются.
При отключении BLib закрывается вся шина; при следующем включении создаётся новая.
Не сохраняйте старый экземпляр шины между перезапусками BLib.

Идентификаторы сравниваются как строки с учётом регистра. Рекомендуемый формат —
`plugin:change`. Отдельные классы событий и зависимости от плагина-источника не нужны.
`null` доставляется каждому подписчику ровно один раз; перебора игроков нет.
История, повторная доставка и автоматическое переключение потоков отсутствуют.

`emit()` читает `ConcurrentHashMap<String, Registration[]>` и обходит массив без
блокировки, итераторов, создания события или других обязательных аллокаций.
Мутации подписок синхронизированы и используют copy-on-write. Каждая публикация
использует один снимок в порядке регистрации. Новые подписчики попадут в следующие
снимки. Перед каждым вызовом читается volatile-ссылка на callback: закрытая подписка
пропускается, даже если присутствует в снимке. Поэтому обработчик может закрыть себя,
закрыть следующего слушателя или рекурсивно вызвать `emit()`.
Уже прочитанный другим потоком callback может завершиться после `close()`;
отписка не ждёт его завершения. Ссылки на закрытые callback и владельца очищаются.

Несколько потоков могут одновременно публиковать, подписываться и отписываться.
Один обработчик может вызываться параллельно: потокобезопасность его состояния и
соблюдение требований Bukkit API остаются ответственностью подписчика.
Ошибка обработчика логируется вместе с идентификатором и именем владельца,
после чего доставка продолжается. Создание сообщения лога происходит только при ошибке.
Bukkit Event API используется исключительно адаптером жизненного цикла плагинов.

## Проверка

```sh
mvn clean verify
mvn -q dependency:build-classpath -Dmdep.outputFile=target/eventbus-classpath.txt
java -Xms256m -Xmx256m \
  -cp "target/test-classes:target/classes:$(cat target/eventbus-classpath.txt)" \
  dev.by1337.core.event.EventBusBenchmark
```

Бенчмарк находится только в `src/test`, не попадает в production JAR и не требует JMH.
На каждый сценарий приходятся 5 прогревочных и 7 измерительных проходов по
5 000 000 публикаций. Callback прибавляет младшую часть UUID к отдельному счётчику;
контрольная сумма проверяется и публикуется через volatile-поле.
Аллокации измеряются через `ThreadMXBean`, если JVM это поддерживает.

Пример запуска на OpenJDK 27, Linux x86_64:

| Подписчиков | Медиана, нс/emit | Измерено байт/emit |
| --- | ---: | ---: |
| 0 | 0.86 | 0.000000 |
| 1 | 8.88 | 0.000000 |
| 5 | 19.70 | 0.000000 |
| 20 | 53.68 | 0.000000 |

Это диагностический микробенчмарк в одной JVM с простыми обработчиками, а не
гарантия задержки в работающем сервере. Результаты зависят от JIT, оборудования
и обработчиков; сравнение с Bukkit Event API не проводилось.
